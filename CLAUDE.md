This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A Flutter app that controls XTRA PR71 pocket routers over their local HTTP API. The phone must be on the router's Wi-Fi; the router exposes JSONP/XML endpoints at a fixed LAN address (`http://192.168.0.1`, see `lib/data/network/api/api_config.dart`). Android is the primary target; the project is in alpha.

## Commands

```bash
flutter pub get                 # install deps
flutter run                     # run on a connected device/emulator
flutter analyze                 # lint (flutter_lints, config in analysis_options.yaml)
flutter test                    # run all tests
flutter test test/network_client_test.dart          # a single test file
flutter test --plain-name "substring of test name"  # a single test by name

# Codegen — required after changing any *_state.dart that uses Freezed
dart run build_runner build --delete-conflicting-outputs

# Play Store screenshot goldens (see test/golden/README.md)
flutter test test/golden --update-goldens   # regenerate goldens/*.png
flutter test test/golden                    # verify only
```

Localization (`lib/l10n/*.arb`, config in `l10n.yaml`) is code-generated by the Flutter tool at build time (`generate: true`); `AppLocalizations` is produced automatically, no build_runner step needed.

## Architecture

Three layers under `lib/`, dependencies pointing inward (`presentation → domain ← data`):

- **`domain/`** — plain entities (`entity/`) and the core `Result<T>` type. No Flutter/HTTP deps.
- **`data/`** — talks to the router and maps responses into domain entities.
- **`presentation/`** — screens + Bloc/Cubit state, organized one folder per feature.

### Request flow (data layer)

Every router call goes: **ApiService → `NetworkClient` → `ResultMapper` + a feature `Mapper` → `Result<Entity>`**.

- `NetworkClient` (`data/network/network_client.dart`) is a singleton wrapping `http.get` with a 5s timeout and a 1 MB response cap. It never throws: transport problems become `Failed` with a `NetworkFailure` classification (`unreachable` / `wrongDevice` / `unknown`). Inject a mock via the `@visibleForTesting` `NetworkClient.testClient`.
- An `ApiService` (`data/network/api/*_api_service.dart`) builds the endpoint URL, calls `NetworkClient`, then runs `ResultMapper().map(result:, mapper:)`. The router returns XML; mappers convert it via `xml2json` → `jsonDecode` → `Entity.fromJson`.
- `ResultMapper` wraps mapping in try/catch so a malformed payload becomes a `Failed` result rather than an uncaught exception, while preserving the transport `kind`.
- **`Result<T>`** (`domain/result.dart`) is a sealed `Successful` / `Failed`; switch over it exhaustively. `NetworkFailure.message` supplies user-facing copy.

### State management (presentation layer)

- Cubits over Blocs. Each feature folder has `bloc/<feature>_cubit.dart` + `<feature>_state.dart`. State classes are either hand-written sealed classes or Freezed (`*_state.freezed.dart` — regenerate with build_runner).
- Cubits typically fetch in their constructor and expose a public `fetch…()` method — the golden-test fakes override that method to inject sample data (see `test/golden/support/fakes.dart`), so keep that method public and network-fetching separable.
- Polling cubits (e.g. `DashboardCubit`, speed gauge) read their interval from `PrefsRepository` `ValueNotifier`s; interval `0` pauses. They keep the last good data on a failed poll (no spinner flicker) and apply mild back-off. Always guard `emit` with `if (isClosed) return;` after awaits.

### Navigation

`go_router` in `presentation/app/router.dart`. Splash → Login → a `StatefulShellRoute.indexedStack` main shell with bottom nav (Home · Contacts/SMS · Messages · Network · Settings), each branch keeping its own stack. Each feature exposes a `<Feature>Route.generateGoRoute()` that wraps the screen in its `BlocProvider`. Full-screen pages (e.g. conversation) are pushed over the shell.

### App shell

`main.dart` initializes `PrefsRepository` (singleton over `SharedPreferences`) before `runApp`. `App` (`presentation/app/app.dart`) wires `DevicePreview` (debug only), theme (`ValueListenableBuilder` on `PrefsRepository().themeMode`), and localizations (`en`, `bn`).

### Demo mode

`DemoMode` (`data/demo/demo_mode.dart`) is a global flag. When enabled, every `ApiService` short-circuits to canned `DemoData` instead of hitting the router — this is how Play reviewers and the golden harness explore the app with no hardware. Logging in with the built-in `demo` / `demo` credentials sets it. When adding a new `ApiService`, honor `DemoMode.enabled` at the top and provide `DemoData`.

## Conventions

- New router feature: add the entity in `domain/entity/`, an `*_api_service.dart` + `*_api_mapper.dart` in `data/network/`, and a feature folder in `presentation/` with a cubit, state, route, and screen — mirror an existing feature (e.g. `network` or `sms`).
- The `test/golden/` goldens are marketing screenshots, not pixel-regression tests. A legitimate UI change that shifts pixels is fixed by re-running `--update-goldens`, not by reverting.
